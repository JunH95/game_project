# 저승·바리데기 — 구현 설계 (design.md)

이 문서는 **구현의 source of truth**다. 코드는 이 문서의 수치·스키마·스코프를 따른다.
서사·설정·비전은 Notion "저승·바리데기" 페이지가 정본이다. 충돌 시 수치·동작은 이 문서가,
스토리·테마는 Notion이 우선한다. 수치나 동작을 바꾸면 코드와 같은 커밋에서 이 문서를 갱신한다.

표기: `[지금]` = M0에서 확정한 기본값(고쳐도 됨, 초안). `[나중]` = 이후 마일스톤에서 결정.
모든 수치는 보수적 초안이며 플레이테스트로 튜닝한다.

시스템 관계·이벤트 흐름·씬 컴포지션 다이어그램은 `docs/architecture.md` 참조(이 문서는 수치·스키마, 그 문서는 관계·흐름).

설정의 사실 근거는 `docs/lore.md` 참조. 이 문서에서 `[고증]`으로 표기한 항목의 출처가 거기 있고,
`[각색]`은 고증 근거 없이 게임을 위해 정한 것이다. 둘을 섞지 않는다.

## 0. 컨셉 요약 (구현 관점)
- 장르: 완결형 뱀서라이크. 탑다운 2D, 자동 공격, 이동만이 유일한 조작 verb.
- 테마: 한국 무속/저승. 주인공 = 무당. 무대 = 저승. 바리데기 모티프(열 관문 → 생명수 → 귀환).
- 차별점: 신내림 — 레벨업 시 능력 대신 "모실 신"을 고른다. 신 조합이 곧 빌드.
- 완성 기준(출시): 시왕 10관문 여정 → 최종보스 → 엔딩까지 도는 **완결 서사** 빌드 + 신당 메타 루프. 신·무기·하드모드 등 폭은 출시 후 확장.

## 1. MVP 코어 루프 `[지금]`
루프: 이동 → 최근접 자동공격 → 처치 → XP 젬 드롭 → 걸어서 수집 → XP 참 → 레벨업(게임 일시정지) →
신 3택1 → 재개 → 관문 타이머 생존.

| 항목 | 값 |
|---|---|
| 시점 | 탑다운 2D, 카메라 플레이어 추적, 고정 줌 |
| 이동 | 8방향, `Input.get_vector("move_left","move_right","move_up","move_down")`, 정규화 |
| 이동 속도 | 120 px/s |
| 픽업 반경 | 40 px |
| 플레이어 HP | 100, 접촉 데미지, 피격 후 i-frame 0.5s |
| 회피/구르기 | 없음 (v1) |
| 공격 | 완전 자동. 공격 버튼 없음 |
| 승패 | 관문 타이머 생존 = 클리어 / HP 0 = 사망 → 정산 |
| XP 곡선 | `xp_to_next(level) = 5 + (level - 1) * 4` → 5, 9, 13, 17 … (선형, 추후 튜닝) |

## 2. 무기 `[지금 형태, 수치는 튜닝]`
작두 = 기본 시작 무기(전원 보유). 부적 = 두 번째 무기, 칠성신 계열로 강화(7발 = 북두칠성).
`[각색]` 원래 설계의 "용왕·수신 해금"은 폐기. 용왕은 문헌 확인된 몸주 사례에 없어 로스터에서 제외했다.

### 작두 (jakdu) — 근접, 자동 부채꼴 베기
최근접 적 방향으로 쿨다운마다 호(arc) 범위를 벤다. 궤도형 칼날이 아니라 "무당이 작두를 휘두르는" 형태.

`[고증]` **작두타기는 상설 절차가 아니라 장군신이 실제로 강림했을 때만 발동되는 조건부 제차다**(lore.md 6절).
따라서 무기 설계를 2단으로 나눈다: **평상시 = 작두 근접 공격(위 형태)** / **장군신 계열 신을 모신 상태에서
조건 충족 시 = 작두타기 발동**(강화 상태 또는 궁극기). 이 2단 구조는 고증과 시스템이 맞물리는 지점이므로
M3(신내림 정식) 때 반드시 반영한다. 발동 조건의 구체 수치는 `[각색]`.

| 파라미터 | 기본값 | 레벨 스케일 |
|---|---|---|
| damage | 10 | 레벨당 +3 |
| cooldown | 0.8 s | 3레벨마다 -0.1s |
| arc (각도) | 100° | 3레벨마다 +20° |
| range | 90 px | - |
| knockback | 120 | - |
| 판정 | 호 범위 내 모든 적 타격 | - |

### 부적 (bujeok) — 원거리, 유도 투사체
최근접 적에게 쿨다운마다 유도 부적 발사.

| 파라미터 | 기본값 | 레벨 스케일 |
|---|---|---|
| damage | 7 | 레벨당 +2 |
| cooldown | 1.2 s | - |
| projectile_speed | 320 px/s | - |
| homing_turn_rate | 4 rad/s | - |
| pierce | 1 | 2레벨마다 +1 |
| count | 1 | 고레벨에서 +1 |
| lifetime | 2.5 s | - |

## 3. 신내림 (god system) `[핵심]`

### 3-1. 몸주 2층 구조 `[고증]`
실제 신앙 구조가 **"모시는 신 여럿 + 그중 1~2위만 몸주(영력의 주체)"**다(lore.md 2절). 이 위계를 그대로 쓴다.

- **몸주 (1위)** — 런의 정체성. 시작 무기·패시브를 결정하고 스탯 스케일링의 원천.
  런 시작 시(캐릭터 선택)로 정해진다. 해금 캐릭터 = 몸주별.
- **모시는 신 (다수)** — 레벨업 3택1로 늘려가는 빌드. 서브 옵션.

이렇게 나누면 **캐릭터 다양성(몸주)과 런 다양성(모시는 신)이 두 축으로 분리**된다.

`[각색]` 3택1·스택·최대 신 수는 게임 수치다. **위계 구조만 고증이다.**
- 레벨업 시 3택1 = (a) 새 신 or (b) 보유 신 +1레벨(VS식 스택)
- 런당 모시는 신 최대 6 (**몸주 1 + 모시는 신 6 = 동시 7신**). 몸주는 레벨업이 아니라 런 시작 캐릭터 선택으로 고정
- 각 신 = `GodData` Resource

### 3-3. 오행(五行) 상성 `[제안, 각색]`
신·무기·적·관문에 오행 태그(木火土金水)를 달아 **관문마다 빌드 유·불리**를 만든다. "아무리 좋은 조합도
관문마다 상성이 있어야 한다"는 요구의 구현. 무속·동양 테마와 맞물려 억지 속성계가 아니다.

- 상극(공격자 오행이 대상 오행을 극): 데미지 **×1.25**
- 역상극(대상이 공격자를 극): 데미지 **×0.80**
- 무관: ×1.0
- 상극 관계: **木→土, 土→水, 水→火, 火→金, 金→木**
- v1은 데미지 배율만. 상생(버프)·속성 UI 표기는 `[나중]`.
- 구현: 데미지 계산 시 `attacker.element` vs `target.element` 룩업(고정 5×5 테이블). 적의 오행은 주로
  관문 오행을 따른다(§5-1). 플레이어를 벌주기보다 **적의 저항/약점**으로 체감시켜 빌드 다양성을 유도한다.

### 3-4. MVP 신 세트 `[제안, 초안 수치]`
M1~M3에서 구현할 최소 신 세트. **MVP 몸주 3**(작도대신·최영장군·칠성신) + **모시는 신 2**(산신·월광보살).
수치는 초안이며 플레이테스트로 튜닝한다.

| 신 | 오행 | 몸주 | 시작 무기·패시브(몸주 시) | 모시는 신 효과(레벨당) | 시그니처(special) |

| 최영장군 | 金 | ○ | 작두, 작두타기 게이지 보유 | 쿨다운 -7%, 이동속도 +5% | 작두타기 발동(합 조건) |
| 칠성신 | 水 | ○ | 부적, 부적 count +1 | 부적 count +1(3레벨마다), 픽업 반경 +12% | - |

### 3-5. 몸주 시그니처 합 `[제안]`
합은 **각 몸주에 묶는다**(몸주당 2~3개) — 조합 폭발을 막고 캐릭터별 빌드 방향을 만든다. 발동 조건 =
해당 두 신 동시 보유. 각 합 = `SynergyData` 인스턴스(§12).

| 몸주 | + 모시는 신 | 합 이름 | 효과(초안) |
|---|---|---|---|
| 작도대신 | 최영장군 | 장군 강림 | 작두타기 게이지 +50%, 발동 시 광역 베기 |
| 작도대신 | 산신 | 궤도 작두 | 작두가 상시 궤도로 주변 회전(damage 60%) |
| 칠성신 | 월광보살 | 칠야(七夜) | 밤 상태에서 부적 착탄 시 소폭발(범위 damage) |
| 칠성신 | 산신 | 북두 방벽 | 부적이 플레이어 주위를 회전하며 방어막 |

- **기본 층**(모든 신 스탯 스택)은 설계 불필요 — 자동 중첩. **합 층**은 위처럼 엄선 페어만. 확장은 `SynergyData` 추가.

## 4. 적 / 스폰 / 웨이브 `[MVP 지금, 확장 나중]`
- **MVP: 추격 적 1종** — HP 10, 속도 60 px/s, 접촉 데미지 8, XP 1 드롭.
- **풀 관문(M5+): 4종** — chaser(스웜) / fast-weak(러시) / tank(고HP) / ranged(원거리 영). 각 `EnemyData` + 공용 enemy 씬.
- **관문별 적** `[제안]`: 공용 아키타입 4종을 밑바탕으로 관문마다 시그니처 적 1~2종 + 오행 태그·리스킨을 얹는다. 적 오행은 관문 오행을 따른다(§3-3 상성). 밑바탕은 재활용, 얼굴만 관문마다(스코프 방어).
- **스폰 디렉터**: 화면 밖 링(반경 ≈ 뷰포트 대각선/2 + 여유)에서 스폰. 시간에 따라 `WaveTable`로 스폰율 증가. 시작 1/s → 버스트로 램프. **동시 적 상한 ~150-200**(노트북 성능, 디렉터 하드캡).
- **원혼 드롭**: 드문 픽업. 처치의 5%가 원혼 1 드롭, 미니보스 10, 관문 보스 25.

## 5. 런 구조 `[지금]`
- **관문 = 5분 타이머 생존 스테이지.** 3:00에 저승사자 미니보스 스폰, 5:00 관문 클리어(또는 관문 보스 처치).
- **런 = 관문 시퀀스 → 최종보스 → 엔딩.**
- **출시 = 시왕 10관문 완주**(완결 서사). 관문은 콘텐츠가 아니라 스토리 척추라 출시에 완성한다. 개발은 화탕 1관문을 완전히 만들어 시스템을 세운 뒤 나머지를 콘텐츠 복제로 채운다(§5-1, §5-2). 신·무기·하드모드 등 폭만 출시 후 확장.
- `[각색 — 중요]` **"시왕 10명 ↔ 지옥 10곳" 1:1 대응은 고증으로 확인되지 않았다**(lore.md 5-2).
  시왕은 지옥이 아니라 재판관이다. 10지옥을 스테이지로 배치하는 것은 **각색**이며, 문서·게임 내에서 고증으로 표기하지 않는다.
  `[고증]`으로 쓸 수 있는 건 시왕 10명의 이름과 **시간축 순서(초칠일~3년)** 뿐이다. 이건 생존 타이머와 잘 맞물린다.
- **삼도천** = 런 전 허브/경계(신당 프레이밍). `[미확인]` 삼도천 개념은 근거 미확보 — 각색으로 취급.
- 런 종료: 사망 → 원혼 정산 → 신당 / 최종 관문 클리어 → 엔딩.

### 5-1. 시왕 10관문 오행/테마 스켈레톤 `[제안, 각색]`
시왕 시간축(초칠일~3년 — lore.md 5-1은 고증)을 뼈대로 각 관문에 오행·테마를 배정한다(木火土金水 각 2관문).
10지옥 명칭·형벌은 `[미확인]`이라 테마는 각색이다. 확정 3 + 제안 7.

| # | 시왕(고증) | 시점 | 관문 테마(각색) | 오행 |
|---|---|---|---|---|
| 1 | 진광왕 | 초칠일 | 도산(칼의 산) | 金 |
| 2 | 초강왕 | 이칠일 | 화탕(끓는 가마) | 火 |
| 3 | 송제왕 | 삼칠일 | 한빙(얼음) | 水 |
| 4 | 오관왕 | 사칠일 | 검수(칼나무 숲) | 木 |
| 5 | 염라왕 | 오칠일 | 업경(업의 거울) | 土 |
| 6 | 변성왕 | 육칠일 | 독림(毒林) | 木 |

- 오행 배치는 상성 다양성용이며 테마·수치는 각색·튜닝. 각 관문 상세(적·기믹)는 그 관문 구현 시 확정.

### 5-2. MVP 관문 = 화탕(火) 완전 설계 `[제안]`
M1~M5에서 시스템을 세우는 기준 관문.

- **오행**: 火. 적 대부분 火 → **水 신(칠성·월광) ×1.25**(수극화), **金 신(작두·최영) ×0.80**(화극금). 순수 작두(金) 빌드는 화탕에서 불리 = 상성 체감 → 수 계열 혼합·전략 전환 유도.
- **적**: 불 원귀(chaser 리스킨, HP 10·속도 60·접촉 8·火) + 시그니처 **용암 정령**(느리고 HP↑, 사망 시 용암 장판 생성·火).
- **기믹 — 용암 웅덩이**: 8초 주기 무작위 위치 생성, 반경 60px, 2초 확산 후 4초 유지, 접촉 시 초당 5 데미지. 안전지대가 주기적으로 좁아진다.
- **타임라인(5분)**: 0:00~1:00 저밀도 도입 → 램프 → **3:00 저승사자 미니보스**(결박 패턴, §6) → 5:00 클리어.
- **배경/톤**: 어두운 가마·용암 붉은빛(§9 — 火 관문 = 주사홍·먹).

## 6. 보스 `[형태 지금, 무브셋 나중]`
- **저승사자** = 관문 미니보스(3:00). `EnemyData`에 `is_boss` 플래그 + 소형 행동 스크립트. 별도 씬 불필요(v1).
  - `[고증]` 저승사자는 단일 존재가 아니라 **역할별로 분화된 계열**이다(lore.md 5-3): 삼성(천황·지황·인황),
    일직/월직사자, 죽음의 종류별 사자(군웅·급살·객사).
  - `[고증]` 일직·월직사자는 *"성명 삼자를 부르고 쇠사슬로 결박하여 끌고 간다"* → **속박(CC) 패턴의 직접 근거.**
    미니보스 시그니처 기믹으로 쓴다: 플레이어를 지목("이름을 부름") → 짧은 텔레그래프 → 결박.
  - `[각색]` 3인조 구성, 사망 원인별 보스 분기는 각색. 3사자/7사자 전승은 단일 제보자 구술이라 절대 규칙이 아니다.
- **관문 보스** = 5:00 (후반 관문은 관문 자체가 보스).
- **최종보스** = 생명수를 지키는 마지막 시왕 관문 수문장. v1 전용 보스 씬 1개. 풀 무브셋 `[나중]`.
- **엔딩** = 정지 일러스트 + 한국어 내레이션(Hades식). 플레이스홀더 = 검정 배경 텍스트.

## 7. 신당 (메타 경제) `[구조 지금, 곡선 나중]`
- **재화: 원혼** — 런 간 영속.
- **획득** = 인런 드문 드롭 + 런 종료 정산: `floor(kills/10) + 관문클리어보너스(각 10) + 보스보너스`.
- **소비** = 신 해금(해금 전엔 런 풀에 미등장) / 장비 티어 강화(작두·부적·플레이어 영구 소폭 상승).
- **비용 곡선(초안)**: 신 해금 30 / 50 / 80 / 120 …, 장비 티어 강화 20 → 40 → 80 → 160 (×2).
- 신당은 v1에서 **단일 메뉴 씬**(탭 2개: 신 해금 / 장비 강화). 신당 건설 시뮬 아님.

## 8. 출시 콘텐츠 스코프 (완결 기준) `[지금]`
**완결 = 서사.** 출시 = 완성된 시나리오 + 시왕 10관문 여정 + 엔딩. 관문은 콘텐츠가 아니라 스토리 척추라 출시에 완성한다. ("3관문 출시 후 확장"은 미완성 스토리라 완결형 정체성과 모순 → 폐기.)
- **출시 포함(서사 완결)**: 캐릭터 1(무당) · 무기 2(작두+부적) · **관문 10** + 미니보스·관문보스 + 최종보스 · 엔딩 · 신당(해금/강화) · 타이틀/설정/세이브 · 코어 신 세트(몸주 + 기본 합).
- **확장 = 폭(출시 후 무료 업데이트)**: 추가 신·무기·몸주(캐릭터), 하드/무한 모드, 합 대량 확장.
- 빌드 순서(M1~M6)는 코어 루프·시스템·관문 1개(화탕) 완성 우선 — 그 뒤 관문은 대부분 콘텐츠 복제라 10관문이 1관문의 10배 작업이 아니다.

## 12. Resource 스키마 (커스텀 Resource 클래스)
`scripts/resources/*.gd`. 모든 콘텐츠는 이 클래스 기반 `.tres` 인스턴스로 `data/`에 둔다.

- **GodData** (`god_data.gd`): `id: StringName`, `display_name: String`, `tier: int`,
  `max_level: int`, `stat_mods: Dictionary`(레벨별 스탯 수정자), `grants_weapon: StringName`,
  `special: StringName`(시그니처 훅, 없으면 빈 값), `icon: Texture2D`, `description: String`,
  `element: StringName`(오행 木火土金水), `is_momju: bool`(몸주 가능 여부), `momju_weapon: StringName`(몸주 시 시작 무기), `momju_passive: StringName`(몸주 시 패시브 훅).
- **WeaponData** (`weapon_data.gd`): `id: StringName`, `display_name: String`,
  `base_damage: float`, `cooldown: float`, `range: float`, `arc_degrees: float`(근접),
  `projectile_speed: float`, `homing_turn_rate: float`, `pierce: int`, `count: int`,
  `lifetime: float`(원거리), `knockback: float`, `is_melee: bool`, `level_scale: Dictionary`.
- **EnemyData** (`enemy_data.gd`): `id: StringName`, `display_name: String`, `max_hp: float`,
  `move_speed: float`, `contact_damage: float`, `xp_reward: int`, `wonhon_chance: float`,
  `is_boss: bool`, `texture: Texture2D`, `radius: float`, `element: StringName`(오행, 상성 §3-3).
- **GateData** (`gate_data.gd`): `id: StringName`, `display_name: String`, `duration_sec: float`,
  `wave_table: WaveTable`, `mid_boss: EnemyData`, `gate_boss: EnemyData`, `background: Texture2D`,
  `clear_color: Color`, `element: StringName`(관문 오행, 적 오행의 기본값).
- **WaveTable** (`wave_table.gd`): 시간축 스폰 스케줄. `entries: Array`(각 항목 = 시작 시각,
  적 `EnemyData`, 스폰율, 버스트 크기). 상세 스키마는 M2/M5에서 확정.
- **SynergyData** (`synergy_data.gd`) `[신설, M3]`: `id: StringName`, `display_name: String`,
  `god_a: StringName`, `god_b: StringName`(두 신 동시 보유 시 발동), `effect: StringName`(시그니처 훅),
  `description: String`. 몸주 시그니처 합(§3-5)을 데이터로 정의·확장.
